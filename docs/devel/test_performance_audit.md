The goal is complete only when every test file and every shared helper/fixture row in the plan has performance evidence, code-analysis notes, potential speedup classification, and any detailed findings or no-finding rationale recorded. Keep the goal command in the markdown for possible future re-runs when tests have changed/added.

## Status legend

- `Not started`: no audit work recorded yet.
- `Measuring`: timing or profiling is underway.
- `Analyzing`: test, fixture, or helper code is being inspected.
- `Done`: performance evidence and code-analysis notes are recorded.
- `Blocked`: progress needs user input or missing tooling.

## Potential legend

- `None`: no credible coverage-preserving speedup found.
- `Low`: small or uncertain speedup, likely not worth immediate implementation.
- `Medium`: localized coverage-preserving speedup with measurable value.
- `High`: repeated or suite-wide cost with clear coverage-preserving mitigation.
- `Unknown`: work has not yet been measured and analyzed.
- `Test-design decision`: a possible speedup would weaken scaling, coverage, assertion strength, fixture realism, or test semantics.

## Findings

### Finding 1: Markdown rule example tests repeated formatter work across three passes

- **Status:** Fixed before this rerun; retained by current analysis.
- **Potential:** Previously Medium; None remaining.
- **Affected rows:** `tests/test_rule_markdown_examples.py`, `tests/markdown_example_helpers.py`, Rule Markdown example execution.
- **Current evidence:** 159 items aggregate `5.110s`; focused examples peak around `0.12s` and the complete expensive group passed 1,032 tests in `13.61s`.
- **Current code analysis:** One parametrized rule-example test now executes settings/selection, initial check, expected fix, hidden-clean direct fix when applicable, and finding correspondence. These are separate guarantees rather than the former duplicated setup across three parametrized tests.
- **Coverage-risk analysis:** Removing a current pass would drop a distinct documented-example guarantee; no further coverage-preserving consolidation was identified.
- **User decision needed:** None.

### Finding 2: Documentation generation was repeated for every consuming test

- **Status:** Fixed.
- **Potential:** Previously High; None remaining.
- **Affected rows:** `tests/test_docs_generation.py`, `conftest.py`, Documentation-site generation.
- **Before evidence:** The file's 64 items aggregated `17.566s`; phase instrumentation attributed `16.728s` to setup because all 39 consumers used a function-scoped generation fixture.
- **Implemented fix:** `generated_site` is module-scoped, allocates its output with `pytest.TempPathFactory`, and uses `pytest.MonkeyPatch.context()` only while generating. Generator path globals are restored before consumer tests execute; every consumer remains unchanged and read-only.
- **After evidence:** The full serial JUnit aggregate for the file is `0.975s`. The focused file passed in `1.33s` with one `0.46s` setup. The full serial suite improved from `46.10s` to `29.35s` (`36.3%`), and default xdist improved from `11.98s` to `6.85s` (`42.8%`) without scheduler changes.
- **Coverage-risk analysis:** Low and verified. All 64 focused tests and both complete suite modes passed; patched globals are restored before tests run. Any future mutating consumer must receive a private copy or narrower fixture scope.
- **User decision needed:** None.
